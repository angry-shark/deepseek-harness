# @deepseek-ai/dsh-client-ui-workspace-ext

[English](README.md) | 中文

工作区增强：输入框工具行的 Git 分支徽章（带锚定的分支切换菜单），以及右侧工作区列（终端 + Git 源代码管理 tab），运行在当前会话工作区目录里的 bash。

**Git 分支徽章** 填充 `conversation.input.left`（输入框工具行，权限等既有控件旁）。它通过全局 `useWorkspaces` hook 读取当前会话的工作区路径，经 node 半解析 `.git/HEAD` 显示分支名（detached 时显示短 sha）。点击徽章弹出锚定菜单，列出全部本地分支（`git for-each-ref`）；点击分支执行 `git checkout` 并刷新徽章，工作区阻止切换时菜单内显示 git 错误。徽章样式与相邻的权限选择器一致：28px 圆角胶囊，含分支 SVG 图标、分支名与旋转下箭头。

**终端面板** 填充 `shell.bottom` 底部轨道，是主列下方的通栏横向面板；**带 tab 的右侧工作区面板** 回到 `shell.right` 右侧列——Git 与「提交历史」（分支 commit 记录）是其中的 tab，收起时右侧栏仅展示这些 tab 按钮。终端对齐 VS Code 终端：分栏填满主区并**左右并排**分屏（「分屏」为活动分组新增分栏，横向渲染），顶部工具条（清屏/终止/启动/新终端/分屏），右侧**纵向 tab 列**列出每个终端——分屏表现为一个 tab 下的多个子 tab（双击标签可重命名）。布局框架关闭时隐藏整条轨道（其高度可从顶部边缘拖拽调整，标题栏「底部」按钮重新打开），展开面板即通过 `subprocess.spawnTerminal` 启动终端。**终端栏** 自动连接：打开面板即通过 `subprocess.spawnTerminal` 在当前工作区目录启动每进程一个的会话，运行用户默认 shell（`process.env.SHELL`，macOS 未设置时为 zsh），并以 `TERM=xterm-256color` 启动。其视口是真正的终端模拟器（xterm.js，与 VS Code 使用同一引擎）：shell 的 PTY 输出流被忠实回放——清屏、光标移动序列、ANSI 颜色、滚动缓冲与全屏程序的行为都与真实终端一致。输出通过 SSE 流实时到达（而非轮询），回显在几十毫秒内渲染；按键直接流向 shell（按序串行，快速输入不会乱序），由 shell 通过该流回显——光标精确地停在提示符之后。终端支持 VS Code 式多终端标签与分屏：标签条列出每个打开的会话（各带关闭按钮），标签切换显示哪个终端——只渲染活动分栏所属分组的分栏，因此「分屏」生成的孪生对即使切换标签也保持堆叠；隐藏的分栏保持挂载，其 xterm 回滚缓冲与流在切换间存活。「新终端」追加一个标签并切换过去；「分屏」在活动会话之后插入新分栏并与之同组；双击标签名即可就地重命名。每个分栏按自身宽度自适应并向前端进程转发实时尺寸变化；面板体在收起或切到 Git 栏时保持挂载，因此终端会继续运行，如同隐藏的 VS Code 面板。**Git 工作区栏** 参考 VS Code 源代码管理面板：顶部为提交框（消息输入 + 提交按钮，回车提交，无暂存内容时智能提交全部变更），摘要行展示分支图标、分支名、变更总数胶囊与领先/落后计数，变更行按「暂存的更改 / 更改 / 未跟踪」分组列出，每条带状态字母徽标与分组计数徽章，并带 VS Code 式交互——分组可用箭头折叠，分组头部提供全部暂存/全部取消暂存/放弃全部更改，悬停变更行会浮现单文件暂存/取消暂存/放弃按钮；点击文件路径打开 Codex 式修改查看器：已跟踪文件显示统一 diff（`git diff`，已暂存文件用 `--cached`），新增/删除/hunk 行分别着色（+/- 代码按文件扩展名经共享 shiki 高亮器做语法高亮），未跟踪文件显示完整原文，并有「返回」按钮回到变更列表。另有手动刷新按钮与 Git tab 上的变更总数徽章。

node 半注册同源路由 `/api/workspace-ext`（`branch`、`branches`、`checkout`、`status`、`diff`、`git/action`、`term/spawn|write|resize|stream|kill|status`）；每个终端路由按 id 寻址一个会话，因此多个分屏终端可并发运行（`spawn` 不带会话 id 时新建，带 id 时原地重启该会话）。该能力可运行 git、可启动并喂给 shell，因此每个 handler 拒绝非回环 Host 头作为 DNS 重绑定防御。

两个目标槽位都由其他插件声明（ui-conversation 与 ui-layout），因此 `apply` 用 `slots.inject()` 按声明生命周期注册，并在声明槽位被恢复后重新注册。

## Model Experience

无。这些界面是浏览器外壳，不进入任何模型请求。

#### KV Cache 影响

无。本包既不组装也不发送 provider 请求。

## 已知限制与后续工作

- **每进程一个终端**——终端会话是进程级的，不按会话区分；切换会话后保持原工作目录，直到终端重新启动。
- **git checkout 无保护**——切换是对工作区直接执行 `git checkout`；除展示 git 错误外没有 stash/冲突解决能力。
- **放弃更改不删除文件**——放弃操作只还原已跟踪的变更（`git checkout`），未跟踪行仅提供暂存；刻意省略 VS Code 式删除未跟踪文件的操作，避免误删文件。
