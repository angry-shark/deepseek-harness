# @deepseek-ai/dsh-client-ui-workspace-ext

English | [中文](README.zh.md)

Workspace enhancements: a git branch chip with an anchored branch switcher in the composer tool row, and a right workspace column (terminal + Git source control tabs) running bash in the current session's workspace directory.

The **git branch chip** fills `conversation.input.left` (the composer tool row, beside the access-mode chrome). It reads the current session's workspace path through the global `useWorkspaces` hook, resolves `.git/HEAD` through the node half, and shows the branch name (or the short detached HEAD sha). Clicking the chip opens an anchored menu listing every local branch (`git for-each-ref`); clicking a branch runs `git checkout` and refreshes the chip, with the git error surfaced in the menu when the working tree blocks the switch. The chip matches the sibling permission selector's chrome: a 28px rounded pill with the branch SVG icon, the branch label, and a rotating chevron.

The **terminal panel** fills the `shell.bottom` track, a full-width horizontal panel below the main columns; the **tabbed right workspace panel** fills the `shell.right` column again — Git and 提交历史 (branch commit history) are tabs, and the collapsed rail shows just the tab buttons. The terminal is modeled on the VS Code terminal: the panes fill the main area and split **side-by-side** (a 分屏 adds a pane to the active group, rendered horizontally), a toolbar (clear / terminate / start / new / split) sits at the top, and a **vertical tab column on the right** lists every terminal — a split appears as one tab with its sub-tabs beneath it (double-click a tab to rename). The layout frame hides the whole track while closed (its height is drag-resizable from the top edge, and the titlebar's 底部 toggle reopens it); expanding the panel spawns the terminal through `subprocess.spawnTerminal` in the current workspace directory. The **terminal tab** auto-connects: opening the panel spawns one session per process through `subprocess.spawnTerminal` in the current workspace directory, running the user's default shell (`process.env.SHELL`, zsh on macOS when unset) with `TERM=xterm-256color`. Its viewport is a real terminal emulator (xterm.js, the same engine VS Code uses): the shell's PTY stream is replayed faithfully — clear-screen and cursor-motion sequences, ANSI colors, scrollback and full-screen programs all behave like the real thing. Output arrives over an SSE stream instead of polling, so echoes render within tens of milliseconds, and keystrokes stream straight to the shell (serialized, so fast typing never reorders), which echoes them back through the stream — the caret sits exactly after the prompt. The terminal supports VS Code-style multi-terminal tabs and split panes: a tab strip lists every open session (each with a close button), and the tabs switch which terminal is shown — only the panes of the active pane’s split group render, so a 分屏 pair stays stacked even across tab switches, while hidden panes stay mounted and their xterm scrollback and streams survive. 新终端 appends a tab and switches to it; 分屏 inserts a new pane right after the active one in the same split group; double-clicking a tab label renames it inline. Each pane fits the panel width and forwards live resizes to its PTY; the panel body stays mounted while collapsed or on the Git tab so the terminals keep running, like hidden VS Code panels. The **Git workspace tab** is modeled on the VS Code source-control panel: a commit box (message input + 提交 button; Enter commits, smart-committing all changes when nothing is staged), a summary row with the branch icon, the branch name, a total-change pill and the ahead/behind counts, then the change rows grouped into staged / unstaged / untracked lists with per-status letter glyphs, change-count badges, and VS Code-style interactions — each group collapses via its chevron, each group header carries stage-all / unstage-all / discard-all actions, and hovering a row reveals per-file 暂存 / 取消暂存 / 放弃 actions. Clicking a file path opens a Codex-style modification viewer: the unified diff for tracked files (`git diff`, or `--cached` for staged ones) with added/deleted/hunk lines colored (the +/- code syntax-highlighted by file extension through the shared shiki highlighter), the full raw text for untracked files, and a 返回 button back to the change list. A manual refresh button and a total-count badge on the Git tab complete the view.

The node half registers same-origin routes under `/api/workspace-ext` (`branch`, `branches`, `checkout`, `status`, `diff`, `git/action`, `term/spawn|write|resize|stream|kill|status`); every terminal route addresses one session by id, so several split terminals run concurrently (`spawn` without a session id creates a new one, with an id it respawns that session in place). The surface can run git and start/feed a shell, so every handler refuses non-loopback Host headers as a DNS-rebinding defense.

Both target slots are declared by other plugins (ui-conversation and ui-layout), so `apply` uses `slots.inject()` to register for each declaration lifetime and re-register after a declaring slot is restored.

## Known Limitations and Deferred Work

- **One terminal per process** — the terminal session is process-scoped and not keyed per session; switching sessions keeps the original working directory until the terminal is respawned.
- **Git checkout is unguarded** — the switch is a direct `git checkout` of the workspace; there is no stash/conflict resolution affordance beyond surfacing git's error.
- **Discard never deletes files** — the discard action restores tracked changes (`git checkout`) but untracked rows only offer staging; VS Code's delete-untracked discard is intentionally omitted to avoid accidental file loss.
