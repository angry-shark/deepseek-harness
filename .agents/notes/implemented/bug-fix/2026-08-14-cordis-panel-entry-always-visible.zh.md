# Agent Note: Cordis 面板入口在清单为空时保持可见

Status: implemented

[English](2026-08-14-cordis-panel-entry-always-visible.md) | 中文

## Problem

Cordis 动态插件注册表只存在于进程内存，因此页面刷新或服务重启后一开始就没有任何定义。每当清单为空时，框架级面板整体什么都不渲染——包括侧边栏底部的角标（`CordisPanel` 中的 `if (all.length === 0) return null`）——所以桌面端重启会移除用户此前用过的插件清单的唯一入口，屏幕上也没有任何说明它为什么消失。

## Decision

`CordisPanel` 在清单为空时仍然挂载底部角标。面板正文本来就区分了加载中、读取失败和真正的空态，所以首次读取前打开显示加载行，读取后显示空态提示。角标现在是跨页面、跨服务重启的稳定框架级入口；定义本身仍然只存在于进程内存，行为不变。

## Alternatives considered

**让定义跨重启持久化。** 拒绝：这与 host-runner「注册表只存进程内存、不写盘」的契约相悖，改动规模也远超这个缺口所需。

**首次读取落定前隐藏角标。** 拒绝：面板在挂载与打开时都会重新读取，短暂隐藏没有任何收益。

## Consequences

侧边栏底部永远带有插件入口，包括新启动、无任何定义的服务；打开后显示空态提示。host-runner 及其持久化契约不受影响，面板在读取落定前保留原有的加载与报错文案。
