# Agent Note: Workspace enhancements (git branch chip + tabbed workspace panel) and the merged plugin-market Cordis tab

Status: implemented

English | [中文](2026-08-16-workspace-ext-git-branch-terminal.zh.md)

## Problem

The GUI offered no per-workspace git or terminal affordances: the composer row showed the access-mode chrome but no current branch, and there was no in-app terminal for the workspace directory. Separately, dynamic Cordis plugin management lived behind its own sidebar-foot entry (`cordis-panel` from ui-cordis), while the plugin market dialog (ui-market) browsed permanent plugins — two entries for two plugin concerns. A custom (non-DeepSeek) OpenAI-compatible provider also failed to load because the desktop runtime excluded the `openai` SDK.

## Decision

A new client plugin package `@deepseek-ai/dsh-client-ui-workspace-ext` ships both workspace surfaces:

- **Git branch chip** (`conversation.input.left`, composer tool row beside the access-mode chrome): resolves the current session's workspace path through the global `useWorkspaces` hook, reads `.git/HEAD` through the node half, and shows the branch (or the short detached HEAD sha). Clicking opens an anchored menu of local branches (`git for-each-ref`); choosing one runs `git checkout` and refreshes the chip, with git's error surfaced in the menu when the working tree blocks the switch. The chip matches the sibling permission selector's chrome: a 28px rounded pill with the branch SVG icon, the branch label, and a rotating chevron.
- **Workspace panel** (`shell.right` layout column, modeled on the VS Code panel): the ui-layout frame gained a fourth column between the details column and the right edge. Like the sidebar, the column participates in the frame's concession chain (details shrinks first, then the right column, then both auto-close; `ctx.layout.toggleRight()` drives the rail ⟷ panel transition), and like the sidebar rail it always renders a compact 40px edge rail when closed (never zero width — the user asked for a right bar that behaves like the left one). The rail stacks the two panel tabs vertically; clicking a tab expands the column on that tab. Expanded it is a tabbed panel: the header holds the tabs and an icon collapse button (the sidebar's panel icon, mirrored for the right edge), and each tab's content carries its own action toolbar (clear/terminate/start for the terminal, refresh for Git). The **终端 tab** auto-connects — opening the panel spawns one session per process via `subprocess.spawnTerminal` in the workspace directory when none is running and a workspace path exists, running the user's default shell (`process.env.SHELL`, zsh on macOS when unset) with `TERM=xterm-256color` (the subprocess spec gained an optional `name`; the plain `dumb` default makes `/usr/bin/clear` a silent no-op because that terminfo entry has no clear capability). Its viewport is a real terminal emulator (xterm.js, the same engine VS Code uses): the shell's PTY stream is replayed faithfully — clear-screen and cursor-motion sequences, ANSI colors, scrollback and full-screen programs behave like the real thing — and keystrokes stream straight to the shell, which echoes them back through the output stream, so the caret sits exactly after the prompt. The terminal fits the panel width (FitAddon + ResizeObserver) and forwards live resizes to the PTY through a new `term/resize` route (the terminal handle gained an optional `resize`); the panel body stays mounted while collapsed or on the Git tab so the terminal keeps running, like a hidden VS Code panel. The toolbar keeps clear (xterm `clear()`; a literal `clear` command also empties the viewport client-side so it works even before the node half runs a real TERM), terminate and start. Multi-terminal and split panes arrived with the node half's session map: `spawn` mints a `term-N` id (or respawns an existing session in place when given one), every terminal route addresses a session by id, and the client renders one pane per session with a VS Code-style tab strip, and the tabs switch which terminal is shown — only the panes of the active pane’s split group render, so a 分屏 pair stays stacked even across tab switches, while hidden panes stay mounted (xterm scrollback and the SSE stream survive the switch); double-clicking a tab label renames it inline). The **Git 工作区 tab’s diff viewer** syntax-highlights the → code: the “+”/“-” lines carry a fixed-width sign gutter and their code renders through the shared shiki highlighter (highlightLines from dsh-client-ui-primitives, now a peer dependency again), colored by the file extension, with lazy grammars re-rendering on load; 新终端 appends a tab and switches to it, 分屏 inserts after the active pane and keeps the pair stacked (any tab or viewport click collapses back to the single view), tabs close their session, and closing the last one stops auto-respawn. The **Git 工作区 tab** is modeled on the VS Code source-control panel: `git status --porcelain=v1 --branch` (branch name, ahead/behind counts) with a summary row carrying the branch icon, the branch name, a total-change pill and the delta, the change rows grouped into staged / unstaged / untracked lists, per-status letter glyphs, change-count badges, a total-count badge on the Git tab, and a manual refresh button. It carries the VS Code SCM interactions too: a commit box (message input + 提交 button; Enter commits, smart-committing all changes when nothing is staged), a chevron that collapses each group, group-header actions (全部暂存 / 全部取消暂存 / 放弃全部更改), and hover-revealed per-file 暂存 / 取消暂存 / 放弃 buttons. The mutations run through a single node-half route `POST /api/workspace-ext/git/action` whose `action` field is allowlisted (`stage` / `unstage` / `discard` / `commit`); `discard` restores from HEAD when the file is staged, and `commit` with `all` stages everything first. Discard only touches tracked changes — untracked rows offer staging only, never file deletion.

The node half registers same-origin routes under `/api/workspace-ext` (`branch`, `branches`, `checkout`, `status`, `diff`, `git/action`, `term/spawn|write|resize|stream|kill|status`); the `diff` route feeds a Codex-style modification viewer in the Git tab — unified diff for tracked files (`git diff`, `--cached` when staged), raw content for untracked ones. `parseGitStatus` decodes the `##` header (branch, detached HEAD, unborn branch, upstream delta) and the two-column porcelain code rows. Because the surface can run git and start/feed a shell, every handler refuses non-loopback Host headers as a DNS-rebinding defense.

The plugin market dialog (ui-market) carries the **Cordis 插件 tab** next to the market tab: a summary list of the session's dynamic Cordis plugins read through the injected `dynamicCordisRunner` Remote (name, plugin id, running state, run-state dot), with ui-cordis's separate sidebar-foot entry rendering nothing. The plugin market backend (`@deepseek-ai/dsh-host-plugin-market`: catalog, git sources, install/uninstall Remotes) is mounted from the web-app bundle layer, so remote browsing and install work; the deployment's workspace-ext copy no longer patches the market surface (its hand-rolled trigger/dialog were removed — the real ui-market owns the sidebar trigger and the dialog). The market trigger is a plain row in the sidebar foot; its styling matches the Settings trigger that sits directly below it (34px row / 36px rail circle, 12px radius, hover fill, label + glyph).

The desktop runtime keeps the OpenAI-compatible path working: `desktop/scripts/assemble-runtime.mjs` excludes the other pi-ai provider SDKs (`@mistralai/mistralai`, `@google/genai`, `@aws-sdk`, `@anthropic-ai/sdk`) so those providers fail loudly with a missing-dependency error, but `openai` stays in the closure — it is self-contained (~13 MB, zero runtime dependencies) and its completions path is the commonest custom-provider route.

## Alternatives considered

**A floating terminal panel instead of a sidebar** — rejected. The user asked for a right bar that behaves like the left sidebar (full-height, collapsible to a rail); the `shell.overlay` implementation mirrors that shape.

**Cross-package import of ui-cordis's CordisPanel into ui-market** — rejected. Package boundaries forbid importing another plugin's symbols; the Cordis tab renders its own summary read from the shared Remote instead of reusing the panel component.

**A child-slot seam for the full Cordis management panel inside the market dialog** — deferred. It preserves the stop/remove/approve panel actions at the cost of a new slot contract and ui-cordis retargeting; the summary tab covers browsing and the run cards cover approvals, so the merge shipped without it.

**Keeping all five pi-ai provider SDKs in the desktop closure** — rejected. Mistral, GenAI, Bedrock, and Anthropic together add ~50 MB of dead weight on every cold start for providers most installs never configure; each keeps its targeted missing-dependency error instead.

## Consequences

The workspace panel, the market trigger alignment, and the openai closure fix ship together in `@deepseek-ai/dsh-client-ui-workspace-ext` (client bundle) and `desktop/scripts/assemble-runtime.mjs` (runtime closure). The panel's `status` route and `parseGitStatus` are new node-half surface; the `git/action` route and the SCM commit/group/file interactions are the follow-up source-control round. The terminal auto-connect changes the panel's behavior from explicit start to start-on-open, so a session with a workspace path spawns bash as soon as the panel expands. The real-terminal round swaps the hand-rolled line renderer for xterm.js and adds `TERM=xterm-256color` plus the `term/resize` route; the latency round replaces the 500ms poll with an SSE output stream (44ms echo in the browser) and the Git tab gains the `diff` route + a Codex-style per-file modification viewer; the multi-terminal round turns the single-session singleton into a session map with id-addressed routes and adds the pane/tab split UI, whose tabs later switch which terminal is shown (a split is a persistent group: tabbing to either member keeps the pair stacked, and closing one member falls back to a sibling first); tab labels are renamable by double-click, the Git diff viewer highlights code through the shared shiki highlighter (dsh-client-ui-primitives is a peer dependency again — imported for the highlighter, not the two icons, which stay inlined), and the right-panel drag ceiling grew from 520 to 760px (RIGHT_MAX). The `openai` closure change grows the desktop runtime by ~13 MB and makes OpenAI-compatible providers resolvable; the other four provider SDKs still require their own missing-dependency error paths if configured. The desktop-shell round gives the installed app a **custom titlebar and bottom terminal**: the Tauri window is undecorated (`decorations(false)`), ui-layout renders a custom `TitleBar` that is the drag surface and, inside the WebView, owns the close/maximize/minimize controls via a restricted `core:window` capability scoped to the harness origin (`withGlobalTauri` + `window-controls` capability); the titlebar also carries a layout menu that toggles the sidebar/details/right/**bottom** panels, and the terminal moved out of the right column into the new `shell.bottom` track (Git stays as a tab there; `shell.right` stays declared but unoccupied). A later refinement returns the **Git workspace panel to the `shell.right` column** (the bottom track is terminal only), makes the bottom panel's **height drag-resizable** from its top edge (ui-layout's horizontal bottom handle), and moves the terminal to the **VS Code model**: split panes render **side-by-side** (horizontal) and a **vertical tab column on the right** lists every terminal, with a split shown as **one tab with its sub-tabs** beneath it (double-click renames; `data-tab-group`/`data-nested` mark the grouping). A later round makes the **right workspace panel tabbed** (`shell.right`): Git and 提交历史 (branch commit history through a new `/api/workspace-ext/git/log` route + `parseGitLog`) are tabs, and the **collapsed right column renders just the tab buttons** (the rail). The app icon (`desktop/build/icon.png`, regenerated by the zero-dependency `make-icon.mjs`) is redesigned: a gradient rounded square with a terminal-window motif (traffic-light dots, a `❯` prompt and cursor). The profile-installed copy (`~/.dsh/profiles/node_modules/@deepseek-ai/dsh-client-ui-workspace-ext`) carries the same client behavior for the running app; its node half needs an app restart to pick up the new spawn `name`, the resize route, and the earlier user-shell changes.
